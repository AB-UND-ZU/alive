# Wiki Build

| Command                                    | Result                                                                                |
| ------------------------------------------ | ------------------------------------------------------------------------------------- |
| `npm run wiki:dev`                         | Stock CRA development server at `http://127.0.0.1:4173`                               |
| `npm run wiki:build`                       | Stock CRA production build in `.wiki-build/`, followed by HTML copies for direct URLs |
| `BUILD_PATH=build/wiki npm run wiki:build` | Build the deployment subtree                                                          |
| `npm run wiki:test`                        | Documentation checks, production browser tests and a live Markdown edit               |
| `npm run wiki:types`                       | Refresh adjacent type documentation                                                   |
| `npm run wiki:references`                  | Refresh generated source links during a running preview                               |
| `npm run wiki:sources`                     | Explicitly refresh item acquisition metadata                                          |
| `npm run wiki:world`                       | Explicitly rebuild seeded Island and town maps                                       |
| `npm run wiki:minimap`                     | Explicitly regenerate the minimap snapshot                                            |

The game and wiki use the same stock CRA entry. `REACT_APP_WIKI` selects the wiki. There are no webpack overrides or separate file watchers. Use `PORT=4185 npm run wiki:dev` to select another development port.

Markdown is fetched and parsed in the browser when its page opens. Player documentation stays in `wiki/`; `src/wiki/pages` is a relative symlink that makes it part of CRA's asset graph. Player and adjacent source Markdown are imported as ordinary file URLs with webpack's built-in context import. CRA handles recompilation and browser reloads. `public/media` exposes the existing wiki images.

`pages.json` is the explicit route and navigation registry. Register a new page there with its source path, title, chapter, group and canonical URL. Aliases preserve older links. Keep separate Gameplay and Development chapters. Source references are generated into the ignored `sourceReferences.json` before every game or wiki CRA start and build, without rewriting Markdown. CRA resolves the wiki imports for both entries. `wiki:references` refreshes them explicitly after an API change during a running preview. Item-source metadata and the minimap are committed snapshots and are not regenerated by builds or previews.

Production assets use `/alive/wiki/`. `scripts/wiki/routes.mjs` copies CRA's generated HTML unchanged to each registered URL, including preview frames and aliases. Direct links return HTML and load the shared bundle; internal links use browser history. This is client rendering, with no prerendering. `PUBLIC_URL=/ npm run wiki:build` builds for local root hosting; `BUILD_PATH` selects `.wiki-build` or `build/wiki`.

`wiki:test` serves the production build using the standard `serve` package and then checks live Markdown updates with CRA. `WIKI_PORT` selects the production test port; the reload test uses the next port. The test servers run sequentially and do not reuse other workspaces' servers.

| Markdown                   | Result                                  |
| -------------------------- | --------------------------------------- |
| `scene` fence              | Isolated game-engine preview            |
| `widget` fence             | Imported data table or interactive tool |
| `[[key:Enter]]`            | Keyboard key                            |
| `[[item:sword iron fire]]` | Item sprite and name                    |
| `[[item:10 arrow]]`        | Count, sprite and item name             |
| `[[button:OPEN]]`          | Game button                             |
| `[[unit:earthChief]]`      | Existing unit sprite and game name      |
| `[[data:20261011-151323]]` | White bracketed data value              |
| `[[stat:xp]]`              | Native colored stat icon and name       |

`App.tsx` renders the page and handles browser history. Routes follow `game-design/<group>/<page>.html` and `development/<group>/<source>.html`; Welcome remains `index.html`. `markdown.ts` parses content, resolves links and supplies Prism syntax tokens. Code fences accept a filename after the language and retain native popup borders, line numbers and Copy. Use `<br>` for separate entries inside Markdown table cells; arbitrary HTML is not accepted.

`GamePreview.tsx` manages isolated frames; `preview.tsx` mounts the game. `Widgets.tsx` imports game data and calculators. The Chat scene uses native dialog completion. Popup widgets show settled native screens; a suffix selects a populated dialog stage such as `forge:add` or `brew:ingredients`.

Readable symbol aliases use the existing stacked text sprites over a selectable source character. The wiki uses the existing DOS font without generating or adding font assets. Body cells are 18 by 32 pixels, headings use three character rows, and scrolling is native.

Write a module's purpose and contracts in its adjacent Markdown before running `wiki:types`. It refreshes declarations below `<!-- source-types -->`, preserving authored examples above. A missing source note stops generation before changing files. The workflow uses Node 24 on Ubuntu 24.04, builds the game and wiki, and publishes `build/` to GitHub Pages.

The Menu, Dungeon and Island pages use `game/menu`, `game/dungeon` and `game/island` scene fences. Island seed 2026 also supplies the full native map and interior settlement references. `wiki:world` explicitly refreshes `island.json`; previews and builds reuse it. Static wiki content has inactive audio output. Samples on Sounds are deliberate; game-frame audio is enabled during interaction and muted on blur, pause or unload.
