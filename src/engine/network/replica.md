# Authoritative client replica

`createReplica` creates a world without gameplay systems. Its `receive` method accepts increasing snapshot sequence numbers and nondecreasing server timestamps, then applies confirmed state in place through `restoreSnapshot`. It preserves entity identity, view-local ownership and render listeners, and removes entities and components absent from the new state. Initial, realm-change and actor-change frames reset render subscriptions; ordinary frames use the same generation checks as single player.

The replica does not execute movement, spells, damage or AI. It does not replay missed snapshots or predict outcomes during a stall. Host frames carry native actor, particle and bump motion models with server start times. The replica restores those models, so mid-animation joins use the authoritative phase rather than starting a new animation. Legacy frames without motion records retarget existing movement springs toward their confirmed positions. Particle offsets and cameras use the same native motion helpers. `render` advances only presentation time, up to one second beyond the last confirmed frame so existing motion can settle during a stall; authoritative elapsed time and component state remain fixed. It does not run sequence callbacks, so damage and other sequence side effects stay server-only. Fast sprite variations currently arrive with snapshots rather than running a second copy of gameplay sequences.

`connectServer` authenticates a browser WebSocket, stores its bearer credential under the normalized server URL in local storage and assigns the authenticated actor to the replica. It refreshes held movement, drops actions during disconnection and resumes with a fresh ordering window after authentication. It never replays a disconnected action backlog. The server resets the owned input mailbox on authenticated reconnect so reloading a page can restart input numbering. Controls, quick use and chat edits send intents instead of changing confirmed components. Chat editing has a separate bounded queue consumed on server frames, rather than waiting for character movement cooldowns. Storage failure stops a new claim before entering the game.

The tests verify stable actor references, component and entity removal, stale-state rejection and that attempted local movement and spell activation cannot run gameplay systems or alter the server world.
