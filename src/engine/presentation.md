# Presentation sequences

Audited decorative callbacks run in the replica without installing gameplay systems. Network snapshots carry their start time and initial arguments, not their transient particles or changing frame counters. The server still runs the original sequences where they have side effects, including weather terrain changes and burn damage.

Read-only popup builders use confirmed tabs, selections and shared data. Forging and sprite editing retain the authoritative renderer because it also processes gameplay/editor actions. Local UI rendering suppresses duplicate sound synthesis; server-owned sound events remain the source of audio.

Player dialog text, discovery markers and personal interaction prompts use local presentation particles. The server sends their start and playing state; clients choose discovery visibility for their own interaction and render character changes at frame speed. Gameplay dialog progression and player message cleanup remain on the server.
